# quant-sma-cpp

Домашнее задание по C++: расчёт простой скользящей средней (SMA).
Кроме самой функции, здесь есть пример запуска, тесты, бенчмарк и сборка
через GitHub Actions.

[Документация](https://mantven.github.io/quant-sma-cpp/)
| [Проверки на GitHub](https://github.com/mantven/quant-sma-cpp/actions)

## Как считается средняя

Функция `quant::simple_moving_average(prices, window)` принимает цены и размер
окна. Например, для цен `100, 102, 101, 105, 107` и окна 3 получаются три средних:

```text
SMA(3): 101.00 102.67 104.33
```

В результат попадают только полные окна, поэтому его длина равна
`N - window + 1`. При сдвиге окна из суммы вычитается старая цена и добавляется
новая. Пересчитывать сумму целиком не нужно, и весь расчёт занимает O(N).

Для суммы используется `long double`, но небольшая ошибка округления всё
равно возможна. Пустой массив, нулевое или слишком большое окно, NaN и
бесконечность вызывают `std::invalid_argument`. Если сумма переполняется,
функция выбрасывает `std::overflow_error`.

## Сборка

Нужны CMake 3.20 или новее и компилятор с поддержкой C++17.
Библиотеки для тестов и бенчмарка уже лежат в `third_party`.

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel 2
./build/quant_demo
```

На Windows с MinGW и Ninja:

```powershell
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel 2
.\build\quant_demo.exe
```

Если используется Visual Studio, команды такие:

```powershell
cmake -S . -B build
cmake --build build --config Release
.\build\Release\quant_demo.exe
```

## Тесты

Для тестов используется doctest. Проверяются обычный расчёт, окна размером
1 и N, отрицательные цены и ошибки во входных данных. Ещё результат
сравнивается с прямым расчётом средней для нескольких размеров окна.

```sh
ctest --test-dir build --output-on-failure
```

Для сборки Visual Studio нужно добавить `-C Release`.

## Бенчмарк

Скорость измеряется через nanobench на массивах из 1 000, 10 000 и 100 000 цен.
Размер окна во всех трёх случаях равен 20. Измеряется весь вызов функции,
включая проверку цен и выделение памяти под результат.

```sh
./build/quant_benchmark
```

В Windows запускается `build\quant_benchmark.exe`, а для Visual Studio -
`build\Release\quant_benchmark.exe`.

Перед замером есть прогрев, затем nanobench несколько раз повторяет расчёт.
В таблице выводятся время на одну цену и количество цен в секунду.
Числа на разных компьютерах могут отличаться. В GitHub Actions таблица
видна в логе и на странице запуска, также её можно скачать в `benchmark-results`.

## Документация

Описание функции берётся из комментариев в заголовочном файле.
Чтобы собрать документацию локально, нужно установить Doxygen и выполнить:

```sh
cmake -S . -B build
cmake --build build --target docs
```

Готовая страница будет в `build/docs/html/index.html`.
В GitHub Actions документация собирается автоматически и после успешного
push в `main` публикуется на GitHub Pages. Ссылка есть в начале README.

## Что запускается в CI

При каждом push и pull request проект собирается в Release. Затем запускаются
тесты, пример, бенчмарк и Doxygen. Если любой из этих шагов завершится с ошибкой,
проверка не пройдёт. Документация публикуется только после успешных проверок
основной ветки.

В этом репозитории Pages уже настроен. При переносе проекта нужно выбрать
**GitHub Actions** в **Settings → Pages → Source** и обновить ссылки в README.

## Файлы проекта

- `include/quant/` - объявление функции и комментарии для Doxygen;
- `src/` - расчёт средней и пример;
- `tests/` - тесты;
- `benchmarks/` - замеры скорости;
- `third_party/` - doctest, nanobench и их лицензии;
- `.github/workflows/ci.yml` - автоматические проверки и публикация;
- `Doxyfile.in` - настройки Doxygen;
- `AGENTS.md` - инструкции для работы с проектом через ИИ-агента;
- `CLAUDE.md` - ссылка на эти инструкции для Claude Code.
